# Life Together Master Library

A source-preserving catalog with LifeTogether as the hub and ten named website entry points. Built from Brett’s supplied **Master campaign list.xlsx**, the verified `claude-artifacts` GitHub tree and README, and explicitly labeled conversation context.

## Open the library

Open `dist/index.html` in a current Safari, Chrome, Edge, or Firefox browser. The standalone file contains its data and UI; no server or account is needed to browse. A browser with `DecompressionStream` support is required. GitHub displays HTML as code, so download it or serve the static directory to use the interface.

For a local web server, run `python3 -m http.server 8080 --directory dist` and open the local address printed by Python. No external packages are required.

## What is included

- **56,853 title-bearing source placements**, without deduplication: 18,569 Updated Master records and 38,284 placements from other source sections.
- All **79 exported sections / 62,826 nonempty data rows**, including raw history, removal logs, supporting outlines, and source summaries.
- **1,088 original artifact links** from **130 archive projects**, including **262 HTML files**. The repository also has rendered wrappers; these are not counted as additional original artifacts.
- **376 initiative pages** from workbook concepts and labeled conversation context.
- **23 named intelligence systems** and their original taxonomy dimensions.
- Title and subtitle detail pages; connected session and devotional outlines where supplied; original fields and source references; archive/project browsing; filters; comparison; device-local collections; CSV and portable collection exports; a basic profile-to-shortlist flow and personalized HTML development briefs.

These counts describe different layers. They must not be added together or represented as finished campaign inventory. “Cataloged” means indexed, not authored or approved. This build does not claim that a title-only record has a complete manuscript.

## Source integrity and holds

`data/source-workbook.csvs.gz` is the losslessly compressed full readable Drive export, with sections separated by form feeds. It preserves cell text, including multiline cells. It is not the original Excel binary: formatting, formulas not exposed by the export, and original worksheet names are not reconstructed. Navigation section names are descriptive labels.

`data/catalog.json` is the portable data model generated by the build; it is not separately committed because the same complete model is embedded in `dist/data.js` and the standalone HTML. Master IDs are unchanged. Other title-bearing placements use stable section/row IDs and retain their source locator. No rows are merged. All history and additional source placements are reference-only in the curation engine, preventing an older duplicate from bypassing a master hold. The 304 explicit “Do Not Send to AI Yet?” master rows, 81 third-party benchmarks, and additional removed/deferred flags remain visible but are not development recommendations. Source raw fields are never overwritten by inferred spoke classifications.

`data/github-artifacts-tree.json` preserves the verified archive tree. `data/archive-index.md` preserves its README, including reconstruction/incompleteness notes. Archive descriptions are source text. File presence is verified; individual files have not all been downloaded, executed, or editorially reviewed. The archive is linked, not duplicated or rehosted.

## Build and verify

1. `python3 scripts/build.py`
2. `node scripts/verify.cjs`

Build requires Python’s standard library. Verification requires Node with web stream support. `src/core.js` owns eligibility and matching; `src/app.js` owns navigation and interface state; `src/catalog-extensions.js` owns the ten doors, intelligence index, and explicit outline joins; `src/style.css` owns the visual system.

Typography uses local Inter when available with a system sans-serif fallback, avoiding external font requests. The catalog uses LifeTogether’s blue working design system. Exported development briefs use the navy/gold palette with local serif/sans-serif fallbacks.

## Deliberate scope boundary

This delivery is the master catalog requested in the latest instruction. It does not activate checkout, price plans, all-access subscriptions, Canva/InDesign handoff, family accounts, saved sensitive profiles, or manuscript generation. It does not implement all 23 intelligence engines or the hundreds of proposed tools. Requested four-/six-session and 7-/21-/30-/40-day options are recorded as development possibilities; the UI displays only the outlines actually present.

The profile flow is a working, rules-based discovery aid. Audience and outcome terms must both match; source priority and explicit duration add ranking weight. It is not the previously approved full family/advisor interview instrument. Mission, values, edition, and stage appear in the exported brief but do not rewrite content. Profile answers stay in the open session; only selected record IDs persist locally. A user can download a collection file for portability.
